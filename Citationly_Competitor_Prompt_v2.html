Fixing the competitor list

What to build, the rewritten prompt, and the six tasks — in that order. The audit of the current prompt is at the back.

Prepared for Arpit Gupta · 5 August 2026 · Sources: locked core flow (2 Aug), PM audit (23 Jul), OpenAI + Gemini API docs

1 · Three onboarding fields this prompt needs and does not have

Start here. The rewritten prompt cannot run on today's onboarding page — it needs three free-text inputs we do not collect. This is the same ticket as blocker B5, not a separate one. Everything else in this document depends on these three fields existing.

FieldWhy the prompt cannot work without it
Who do you sell to?
free text, ~1 line, required		 The substitution test is meaningless without a buyer. "Who would this buyer choose instead of you" needs a buyer. The audience chips (CEO / CMO / Agency) describe a job title, not a customer — io-ai sells to AI labs and robotics companies, and no chip says that.
Competitors you already know of
free text, optional, comma-separated		 Blocker B5. Two jobs: it anchors the model in the right neighbourhood, and it is the honest fallback when the derivation returns fewer than three. Also feeds the blacklist counterpart, never_include.
Your main offering
one line, prefilled from the extractor with an "AI Suggested" badge		 Only bites on multi-product companies, but it bites hard. For a HubSpot or a Zoho, what_they_sell is one blob spanning CRM, marketing, support and CMS — so eight competitor slots get spread across four categories, and each re-derivation anchors on a different product line. The set is unstable by construction, which breaks trend tracking. One line naming the main thing fixes it. Reuse the prefill-plus-badge pattern that already works for Industry.

The existing Products / services box already carries what_they_sell correctly — that field is fine as-is and should be marked required. industriesServed from the extractor must not be passed to this prompt at all.

CITATIONLY — COMPETITOR DERIVATION PROMPT  v2.1
Stage: Calibrate (Gate 2). Runs once per workspace, and on demand from Settings.
Portable: identical text on OpenAI and Gemini. Only the schema binding differs.

---------- SYSTEM MESSAGE ----------

You identify the commercial competitors of a business.

You are accurate before you are complete. A short correct list is a success; a
long plausible list is a failure. You never invent a company. If you are not
confident a company exists and sells what you say it sells, leave it out.

You return JSON only, conforming exactly to the supplied schema. No prose,
no markdown, no commentary outside the JSON.

---------- USER MESSAGE ----------

## BUSINESS
Use only the fields below. Do not infer facts that are not stated here.

company_name:        {{company_name}}
website:             {{root_domain}}
primary_offering:    {{single_main_thing_they_sell}}
what_they_sell:      {{core_services_and_products}}
who_they_sell_to:    {{buyer_description}}
buyer_type:          {{B2B | B2C | B2B2C}}
primary_market:      {{primary_country}}
other_countries:     {{other_countries_served}}
company_stage:       {{stage}}
known_competitors:   {{user_seeded_competitors}}
never_include:       {{user_blacklist}}
current_locked_set:  {{domains_already_locked_or_empty}}

GROUNDING RULE — this is not optional.
The ONLY sources of competitor names are `primary_offering`, `what_they_sell`
and `who_they_sell_to`. Geography, company stage, SEO keywords and the
industries this business serves are NEVER sources of competitor names. If a
company came to mind because of a country, an industry, or a keyword rather
than because it sells the same thing, do not return it.

MISSING FIELDS: if `what_they_sell` or `who_they_sell_to` is empty, or says
only "Other", do not guess. Return an empty competitor list with
status = "missing_input" and name the missing field in what_would_help.

MULTI-PRODUCT BUSINESSES: if `what_they_sell` spans several unrelated product
lines, derive competitors for `primary_offering` ONLY. Do not spread the list
across product lines — a set that changes focus between runs is useless for
tracking over time.

## THE TEST FOR "COMPETITOR"
A competitor is a company that a buyer matching `who_they_sell_to` could choose
INSTEAD OF {{company_name}} to get the same job done — or that such a buyer
would see recommended alongside {{company_name}} as an alternative choice for
that same need.

Substitution is the test. Not similarity, not adjacency, not "same industry",
not "appears in the same articles".

A company is NOT a competitor if it would more plausibly BUY from
{{company_name}}, SUPPLY it, PARTNER with it, or RESELL it.

Size is not part of the test. A company ten times larger that a buyer would
consider instead IS a competitor.

## WHAT TO RETURN
Name up to {{max_competitors}} companies that pass the test above.
Returning fewer is correct and expected. Returning zero is correct when the
input does not support a confident answer.

## STABILITY — read this before you start
If `current_locked_set` is not empty, those companies are already being tracked
over time and the customer's historical numbers depend on them.

  - Return every company in `current_locked_set` unchanged, unless it now fails
    the competitor test or a hard exclusion. If you drop one, say why in
    why_competitor, prefixed "DROPPED: ".
  - Any new company you would add is a PROPOSAL. Return it normally; the
    application decides whether to add it. Do not attempt to swap one out.
  - Do not re-order the locked companies for cosmetic reasons.

## PRECEDENCE — apply in this order, top wins
  1. `never_include`               — always removed, no exceptions.
  2. {{company_name}} itself, its parent, subsidiaries, former and trading
     names, and any brand it owns — always removed.
  3. `known_competitors` supplied by the user — always included, source="user".
     Fill every field honestly and set model_agrees to your true view, even if
     that is false. Never silently drop one.
  4. `current_locked_set`          — retained per the stability rule above.
  5. Companies you name yourself    — source="model".
If rule 3 and 4 together already exceed {{max_competitors}}, return them all
and add nothing of your own; note the overflow in what_would_help.

## HARD EXCLUSIONS
1.  Companies drawn from the INDUSTRIES THIS BUSINESS SELLS INTO. If
    {{company_name}} sells to defence, robotics or automotive firms, then
    defence, robotics and automotive firms are its CUSTOMERS, not its rivals —
    unless that company also sells the thing described in primary_offering.
2.  Anything that is not a company selling this: review sites and directories
    (G2, Clutch, Capterra, TrustRadius), marketplaces, listicles, blogs, media
    outlets, conferences, job boards, subreddits, open-source projects with no
    commercial vendor behind them.
3.  Generic consultancies, agencies or staffing firms — UNLESS
    {{company_name}} is itself a consultancy, agency or staffing firm, in which
    case peer firms of that kind are exactly the right answer; or unless a
    named, productised offering of theirs directly substitutes for
    primary_offering.
4.  Companies you believe have ceased trading.
5.  Any company you are not confident actually exists.

DO NOT exclude a company for being much larger than {{company_name}}.
Record size in `relative_scale`; never use it to filter. The buyer sees the
market leaders whether or not this business is their size.

DO NOT substitute a parent or acquiring company for a brand. If a product still
sells under its own name, return that name and that domain. Corporate ownership
changes faster than your knowledge of it, and naming an acquirer is how a
mega-cap ends up in a small business's competitor set.

## RANKING
Order by SUBSTITUTION LIKELIHOOD — how often a buyer matching
`who_they_sell_to`, making a real choice, would have this company in front of
them alongside {{company_name}}. Most likely first.

Two tie-breakers, in order:
  a. Companies that sell into `primary_market` rank above those that do not.
  b. Companies whose offering overlaps `primary_offering` most directly rank
     above those with partial overlap.

Never rank by size, fame, funding, or alphabetical order.

## CONFIDENCE — use these anchors, do not drift
  90-100  I can name this company's own page for this exact offering.
  70-89   I am certain they sell in this category; less certain the overlap is direct.
  50-69   Plausible category match; I cannot confirm the overlap.
  below 50  Do not return it — unless it is a user-supplied company, which you
            must return with your honest low score and model_agrees = false.
Whole integers only.

## BEFORE YOU ANSWER — mandatory self-check
Re-read your list once. For each company ask:
  "Would this company more plausibly be a CUSTOMER of {{company_name}}
   than a rival to it?"
If the honest answer is yes, delete it and record it in excluded_notable.
Also delete any company you added because it is famous, because it shares a
country, or because it appears in the same articles — rather than because a
buyer would actually choose it instead.

If fewer than 3 companies survive, that is the correct answer. Set
status = "thin_market". Never pad the list to reach a number.

## FIELD DEFINITIONS — all of these are graded, none are optional
name                  Common trading name. Not the legal entity name.
domain                Canonical root domain: lowercase, no scheme, no "www.",
                      no path, no trailing slash. THIS IS THE IDENTITY KEY —
                      it is used to join records across runs and engines. Give
                      the domain you are most confident is correct. If you are
                      unsure of the exact domain, still give your best answer
                      but cap confidence at 69.
hq_country            ISO 3166-1 alpha-2, uppercase (US, IN, GB, DE). Use "ZZ"
                      if you do not know.
relative_scale        smaller  — materially smaller than {{company_name}}
                      peer     — same order of magnitude
                      larger   — materially larger, but not the category leader
                      category_leader — one of the 2-3 best-known names buyers
                                        reach for first in this category
                      unknown  — you cannot judge
serves_same_market    true only if they actively sell into `primary_market`.
                      If you do not know, false.
why_competitor        <= 20 words. What they sell that overlaps primary_offering.
                      Concrete. No marketing adjectives.
their_edge_vs_client  <= 20 words. Why a buyer might pick them over
                      {{company_name}}.
client_edge_vs_them   <= 20 words. Where {{company_name}} wins. Write
                      "unclear from the input" rather than inventing an
                      advantage.
basis                 named_direct_rival    — widely and specifically known as a
                                              rival of this company
                      known_category_vendor — I know this company sells in this
                                              category; the head-to-head is my
                                              judgement
                      inferred_from_description — reasoned from the description
                                              alone. Cap confidence at 69.
confidence            Per the anchors above.
model_agrees          true if you independently believe this is a competitor.
                      Always true for companies you named yourself. For
                      user-supplied companies, your honest view.
source                "user" if it came from known_competitors or
                      current_locked_set, otherwise "model".
status                ok | thin_market | missing_input
what_would_help       One sentence naming the single input that would most
                      improve this result. Empty string "" when status is "ok".
excluded_notable      Up to 5 companies you seriously considered and rejected,
                      each with a one-line reason. Used to audit this prompt.
                      Be candid — this field is read by humans, not customers.

Respond with JSON only.

GATES THAT LIVE IN CODE, NOT IN THIS PROMPT
================================================================================
The prompt is a request. Code is a guarantee. Enforce these after the model
returns, never by asking the model nicely:

  1. ENTITY LIVE      — resolve every `domain` over HTTP. Non-resolving, parked,
                        or redirect-to-unrelated => drop the row. The prompt
                        deliberately does not claim to know what is live; an
                        ungrounded model cannot know.
  2. DOMAIN REPAIR    — before counting agreement, normalise each row to a
                        resolved entity: strip www/scheme, follow redirects,
                        and fuzzy-match name+domain against rows already seen.
                        Models emit surge.ai for surgehq.ai and samasource.org
                        for sama.com. Un-repaired, one real competitor named
                        10/10 splits into two 5/10 rows and both get discarded.
  3. SELF / ALIAS     — drop the client's own domain and every known alias.
  4. BLACKLIST        — drop everything in never_include, even source="user".
  5. NOT-A-VENDOR     — drop known directory, review and marketplace domains
                        from a maintained denylist.
  6. SET SIZE         — LOCKED tier truncated to 8 by appearance count, then by
                        substitution rank. Fewer than 3 survivors triggers the
                        user ask; it never pads.

5 · Appendix — why the comparison run is also the algorithm

Background for C4 and C5. Not needed to start work.

You proposed running both APIs five times to compare. Do that — but do not treat it as a one-off QA exercise. The comparison is the algorithm.

A hallucinated competitor is, almost by definition, unstable: it comes from a weak statistical association and does not survive resampling, and it very rarely survives a different model's training data. A real competitor is stable across both. So:

For each RESOLVED ENTITY, count appearances across 10 runs (5 ChatGPT + 5 Gemini):

  both engines, >= 4/5 each    ->  LOCKED     auto-include, truncated to 8
  both engines, >= 2/5 each    ->  CANDIDATE  show at Gate 2, pre-ticked
  anything else with >= 3/10   ->  WEAK       show at Gate 2, un-ticked
  <= 2 appearances of 10       ->  DISCARD    this is where hallucinations live

  fewer than 3 LOCKED          ->  fall through to the "who do you compete
                                   with?" ask. Never pad.

This replaces the model's self-reported confidence — which is fiction — with a measured one. It costs 10 calls once per workspace, at competitor-derivation time only. At current API pricing that is cents, against the ~$25–35/month per account the scan budget already carries.

The one way this algorithm quietly fails

It counts resolved entities, not raw model output. Models routinely emit surge.ai for Surge AI (really surgehq.ai) and samasource.org for Sama (really sama.com). Without a normalise-resolve-merge step first, one real competitor named in all 10 runs splits into two 5/10 rows — or two 1/10 rows — and lands in DISCARD. The most stable competitor in the set becomes the one you throw away. Resolve and merge before you count.

Second-order benefit

It gives you a number to put on the trust problem: "this competitor was named by both ChatGPT and Gemini in 9 of 10 independent runs." That is a receipt, in exactly the format the rest of the product is being rebuilt around — and it is a line no competitor tool can currently show.

A rule this forces us to decide now

The locked set is the denominator for every trend we will ever show. So a re-derivation in month three must not quietly return a different 3–8 — that would reset the baseline and make every historical Presence % uncomparable, which is the same class of bug as the four disagreeing composite scores.

Rule: re-derivation never auto-swaps. The current locked set is passed back into the prompt and returned unchanged unless a member now fails a gate. Anything new is a proposal, surfaced to the user with "adding this resets your baseline" — the same warning already agreed for promoting a revealed rival. v2.1 implements this via the current_locked_set input.

6 · Appendix — rating the current prompt

Why we are replacing it at all. Read only if you want the reasoning behind each change in §2 — nothing here is a task.

4/10

Right instincts, wrong job. It is a politeness filter bolted onto a pipeline whose actual defect sits upstream of it — and one of its instructions actively damages the product.

What it gets right (the 4 points)

  • "Returning fewer is correct and expected." Rare and valuable. Most prompts silently pressure the model to fill the quota, and quota-filling is where hallucinations come from. Keep this sentence forever.
  • Explicit ordering instruction. Without it the model returns fame order.
  • Word caps on the free-text fields. Stops the model writing essays that break the UI.
  • Pinning confidence to a whole number. Someone was clearly burned by 0.85 vs 85. Good defensive instinct.

Why it loses the other 6

fatalIt never says what a competitor is

The prompt uses the word "competitor" as if it were self-defining. To a language model it is not. "Competitor" plus a business description reliably retrieves companies that co-occur with this one in text — which includes its customers, its suppliers, its partners and its resellers. This single omission is the whole Lockheed Martin / Waymo / Boston Dynamics / TaskRabbit failure. The fix is one sentence: a competitor is who a buyer would choose instead of you. Substitution, not similarity.

fatalIt filters candidates but never grounds them

"the Business above" does all the load-bearing work and this prompt has no control over what that block contains. Per the 2 Aug root-cause finding, the context block feeds the extractor's industriesServed field — the list of industries the client sells into. So the model is asked to filter a candidate pool that was poisoned before it arrived. You can score this prompt 10/10 and still get Lockheed Martin. v2 therefore names what_they_sell and who_they_sell_to as the only permitted grounding, and adds an explicit exclusion for the sell-into industries.

fatalThe scale rule is backwards for this product

"…or that is a broad category-dominating giant clearly larger than this business's own scale"

This instruction tells the model to delete Scale AI, Appen and Labelbox from io-ai's competitor set. Those are precisely the three companies our own Answer Simulator caught splitting the AI answer while io-ai was absent. Citationly's job is to report who appears in the AI answer instead of you — and the answer is dominated by category leaders. A competitor set that excludes them measures a market that does not exist.

Worse, it is compounded by {ctx.Scale}, which is self-declared at onboarding. A founder who ticks "startup" gets a competitor set of other startups, a flattering Presence score, and a product that has told them a comfortable lie.

v2 tags scale instead of filtering on it — relative_scale ∈ smaller / peer / larger / category_leader. The UI can then segment "your weight class" vs "the whole field" and the user decides. Same information, no blindness.

majorNo domain field — so nothing downstream can work

The output is keyed on a company name. Names do not join: "Scale AI" / "Scale" / "Scale AI (Meta)" are three rows. Without a canonical root domain you cannot run the entity-live gate from the locked flow, cannot dedupe, cannot blacklist, and cannot compare ChatGPT output against Gemini output — which is the experiment you are about to run. domain is the single most valuable field to add.

major"FAIR" in capitals is emphasis, not instruction

"Genuine, FAIR competitors" — capitalisation raises the model's attention on a word that carries no operational meaning. To a model, "fair" reads as reasonable / balanced. It does not read as "comparable scale", which is what was intended. Every rule in a prompt must be testable by the model against the input. Replace adjectives with tests.

majorconfidence is formatted but not calibrated

The prompt specifies the number's shape and not its meaning, so every model returns 85–95 for everything, including the hallucinations. An uncalibrated confidence score is worse than none — it launders a guess as a measurement. v2 anchors each band to a statement the model can actually evaluate, and forbids returning anything below 50.

minor"Same business model" over-restricts

A managed-service annotation vendor and a self-serve annotation platform absolutely compete — same budget, same shortlist, same AI answer. Business-model similarity is a ranking signal, not an exclusion criterion. v2 demotes it accordingly.

minorstrength / weakness are undefined, and geography is unused

Whose strength — theirs in absolute terms, or theirs relative to the client? Undefined, so the model picks per row and the fields cannot be compared. v2 makes both explicitly relative to the client, which is also exactly what the Tell stage needs ("competitor strengths → the client's gaps").
